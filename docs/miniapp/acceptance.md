# Приёмка работ по Mini App

Кто принимает: **Claude**. Итог приёмки: «принято», «принято с замечаниями» (мелочи, которые не мешают следующим частям; они записываются в бэклог) или «на доработку» (список пунктов со ссылками на ТЗ).

## 1. Что присылает исполнитель
- Ветку `miniapp/<часть>` от актуальной основной ветки, без merge-коммитов из чужих веток.
- Отчёт: по каждому пункту ТЗ — сделано / не сделано / сделано иначе (с причиной); список новых файлов; известные проблемы.
- Вывод `npm test`, `npm run e2e` и скриншоты из `tests/e2e/__screenshots__/`.

## 2. Что проверяет Claude

### 2.1. Границы
- [ ] Изменены только файлы, разрешённые ТЗ (`miniapp/…`; для M3/M4 — только свои `src/games/<kind>/…`, `registry.ts`, свои тесты).
- [ ] `games_core/`, `sea_fight_aiogram/`, `max_bot/` не тронуты (иначе — отдельное согласование).
- [ ] Зависимости — только из списка ТЗ; `package-lock.json` обновлён и согласован с `package.json`.
- [ ] `src/protocol.ts` совпадает с контрактом (`README.md` §4, `tz-m1-core.md` §3); если исполнитель нашёл расхождение — оно в отчёте, а не молча исправлено.

### 2.2. Сборка и тесты (Claude запускает сам, не верит отчёту на слово)
- [ ] `npm ci && npm run build` — без ошибок и предупреждений TypeScript; размер бандла в пределах ТЗ.
- [ ] `npm test` — зелёный; снимки DOM осмысленные (не пустые, не обновлены «вслепую»).
- [ ] `npm run e2e` против `miniapp/dev-server.sh` — зелёный на обоих вьюпортах и в обеих темах.
- [ ] `.venv/bin/python -m pytest` — зелёный (сервер и ядро не сломаны).

### 2.3. Поведение
- [ ] Клиент не содержит правил игр: нет проверок «верная ли клетка», нет своих таймеров фаз; payload'ы — только из `view.actions` и `button.data`.
- [ ] HTML от сервера рендерится только через безопасный рендер (поиск по коду: `innerHTML`, `dangerouslySetInnerHTML` — только внутри `html.ts`, если вообще).
- [ ] Быстрые нажатия подряд (10 за секунду) не ломают экран: e2e или ручной прогон через dev-сервер.
- [ ] Разрыв связи и возврат — экран восстанавливается, дублей нажатий нет.
- [ ] Тёмная тема: контраст текста и клеток читаем (скриншоты).
- [ ] Поле самого большого уровня влезает на 360×640.

### 2.4. Код
- [ ] TypeScript `strict`, без `any` в контракте, без мёртвого кода и закомментированных кусков.
- [ ] Компоненты небольшие; общее вынесено в `src/app/`, а не скопировано между играми.
- [ ] Комментарии по-русски там, где неочевидно «почему».

## 3. Как оформляется результат
Claude пишет итог в `docs/miniapp/reviews/<часть>-<N>.md`: вердикт, что проверено (команды и их вывод кратко), список доработок с пунктами ТЗ и файлами. Тот же текст — пользователю и исполнителю.

## 4. После «принято»
Claude вливает ветку в основную, обновляет `README.md` (статус этапа) и, если нужно, `fixtures/`. Выкладка в прод — только по команде пользователя (M5/M6).
