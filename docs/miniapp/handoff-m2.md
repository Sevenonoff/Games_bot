# Задача M2 для исполнителя: каркас фронтенда Mini App

Это поручение целиком — его можно отдать модели-исполнителю как есть. Техническое задание — `docs/miniapp/tz-m2-shell.md`, здесь — как к нему подступиться, что можно и что нельзя, как сдавать.

---

## Кто ты и что делаешь

Ты делаешь фронтенд Telegram Mini App для бота развивающих игр. Сервер уже готов: он отдаёт экраны бота по WebSocket. Твоя часть — приложение `miniapp/`, которое:
- подключается к серверу;
- показывает любой экран «текст + кнопки» универсальным рендером;
- даёт точку подключения для экранов игр (их сделают следующие этапы M3/M4).

Правил игр на клиенте нет и не будет: клиент только показывает экраны и шлёт нажатия.

## Прочитай до начала (по порядку)
1. `docs/miniapp/README.md` — архитектура и **протокол WebSocket** (§4). Это контракт: его не меняй.
2. `docs/miniapp/tz-m2-shell.md` — **твоё ТЗ**, по нему принимают работу.
3. `docs/miniapp/tz-m1-core.md` §3 — схемы `view` экранов игр (тебе нужны только для типов в `src/protocol.ts`).
4. `docs/miniapp/fixtures/*.json` — настоящие кадры сервера: меню (`menu.json`), экраны без `view` (`sea-menu.json`, `ai-level.json`, `result-memo.json`) и игр. По ним удобно верстать без сервера.
5. `docs/miniapp/acceptance.md` — как будут проверять.

## Окружение (машина 89.125.106.7, пользователь clawuser, sudo нет)
- Node 22 и npm уже есть.
- Сервер для разработки: `miniapp/dev-server.sh` (порт **8448**, своя БД, Telegram не трогает, вход `dev_user` только с localhost). Боевой бот работает на этой же машине — **не запускай** `sea_fight_aiogram/main.py` и `run.py` и не трогай сервис `games-tg-bot`.
- Playwright: `npx playwright install chromium-headless-shell`. Системных библиотек Chromium на машине не хватает, они подложены в `~/.local/lib/playwright-deps`. Запускай e2e с `LD_LIBRARY_PATH=$HOME/.local/lib/playwright-deps` (пропиши это в `npm run e2e` или в `webServer`/`use.launchOptions.env` конфига). Шрифт эмодзи стоит в `~/.local/share/fonts`, на скриншотах эмодзи цветные.
- Проверка, что всё работает: `miniapp/dev-server.sh`, затем в браузере или скриптом WebSocket `ws://127.0.0.1:8448/ws` → `{"type":"hello","dev_user":{"id":1,"name":"Тестер"}}` — придёт меню.

## Ветка
`git switch -c miniapp/m2-shell` от ветки `main` (коммит `289378a` или новее). Коммить по ходу работы осмысленными шагами; в конце ветка должна собираться и проходить тесты.

## Можно / нельзя
- Можно: всё внутри `miniapp/`, кроме `miniapp/dev-server.sh`; `.gitignore` (только строки для `miniapp/`).
- **Нельзя** без согласования: `games_core/`, `sea_fight_aiogram/`, `max_bot/`, `tests/` (питоновские), `docs/miniapp/` (кроме отчёта, см. ниже). Нашёл ошибку или неудобство в сервере или протоколе — опиши в отчёте, не исправляй сам.
- Зависимости — **только** из списка ТЗ §2. Нужна другая — вопрос в отчёте, а не установка.
- Тексты экранов приходят с сервера. Свои подписи на клиенте — только служебные: «Нет связи…», «Откройте игры из Telegram», «скоро». Весь текст интерфейса — по-русски.
- Комментарии в коде — по-русски (как во всём репозитории), имена — по-английски. TypeScript `strict`.

## Что сдать
1. Ветку `miniapp/m2-shell`: `npm ci && npm run build && npm test && npm run e2e` проходят из `miniapp/` с нуля.
2. Отчёт `docs/miniapp/reports/m2-shell.md`:
   - по каждому пункту ТЗ §3 и §5 — «сделано / не сделано / сделано иначе — почему»;
   - отступления от ТЗ и найденные проблемы сервера или протокола;
   - размер бандла (gzip) и вывод трёх команд выше (хвосты);
   - список скриншотов e2e. Сами файлы лежат в `miniapp/tests/e2e/__screenshots__/`, в git их не клади.
3. Ничего не выкладывай и не перезапускай на сервере — выкладка не входит в M2.

## На что обратят внимание при приёмке (коротко из `acceptance.md`)
- Клиент не знает правил: payload'ы берутся только из `button.data` и `view.actions`.
- HTML с сервера — только через безопасный рендер, без `innerHTML`/`dangerouslySetInnerHTML` со строкой сервера.
- Быстрые нажатия подряд и разрыв связи не ломают экран и не дублируют нажатия.
- Тёмная тема читается, на 360×640 ничего не обрезано.
- `src/protocol.ts` ровно по контракту.

Вопросы и спорные места — в отчёт. Если что-то в ТЗ мешает сделать хорошо, предложи, как лучше, и сделай по ТЗ, пока не согласовано.
