## Доработки

1. **Линия дороги рисуется мимо клеток (ТЗ §5) — главное.**
   - Скриншоты `path` `03-road` и `04-done`: на 414 линия игрока идёт вниз далеко за поле, через клетку с человеком и в пустоту; на 360 горизонтальный отрезок лежит на полклетки ниже кружков.
   - Причина: `.field` растягивается по высоте флекс-родителем `.field-scroll` (`align-items: stretch` по умолчанию). SVG с `inset: 0; height: 100%` получает высоту всей зоны, а `preserveAspectRatio="none"` растягивает координаты по вертикали. Вторая, меньшая неточность — `viewBox` в единицах клеток не учитывает `gap` 4 px, поэтому центры смещаются к краям поля.
   - Как лучше: SVG размером ровно с сетку в px, координаты центра — `c * (cell + gap) + cell / 2`; `cell` у тебя уже есть в `Field`. Плюс `align-self: start` у `.field`, чтобы сетка не тянулась.
   - На `done` дорога должна читаться от человека до дома: включи клетки `person` и `house` в построение отрезков вместе со `step`.
   - Проверка в e2e (в Chromium, jsdom тут ничего не ловит): на `done` для каждого отрезка `line` концы попадают внутрь прямоугольников соседних клеток (`getBoundingClientRect` линии ⊂ объединения двух клеток). Плюс скриншоты `done` и `review` на 360 и 414.
2. **Изоляция e2e (ТЗ §7.3: «Пересечений между тестами нет»).** `userId(base, project)` = `base + 0…3`, а базы соседних тестов отличаются на 1. Пересечения:
   - игроки:
     - `memo` 201/202/203 делят 202–205;
     - `tower` 221/222 делят 222–224;
     - при повторе `memo-leak` r1 = 231 совпадает с `path-full` r0;
   - админы: `matrix` 14×7 r1 (310+25 = 335–338) совпадает с `path` «ошибка» r0 (335–338).

   На этой машине тесты идут в один поток, поэтому мешают друг другу только через накопленный уровень. С 4 потоками это гонка за одну партию (и `dbg` прерывает открытую). Нужно:
   - базы тестов с шагом ≥ 4: id = база + номер проекта, все id — в диапазоне 200–299, админы — 300–399;
   - повторы — так, чтобы `--repeat-each=2` не выходил за диапазон и ни с чем не пересекался.

   Пример раскладки: тест *k* (0…12) → база `200 + 4k`; повтор — `+ 52` для игроков (до 299) и по той же схеме для админов. Положи раскладку одной таблицей-комментарием в начале каждого spec или в одном своём модуле `tests/e2e/m3-ids.ts`.
3. **Поле меняет размер между кадрами; синтетические клики (ТЗ §1.3, §7.3).**
   - Размер клетки зависит от высоты зоны, а она — от высоты подсказки (`.game-hint` — `flex: 0 0 auto`, `.field-scroll` — `flex: 1`). Подсказка меняет число строк между фазами («Приготовьтесь» — 1 строка, подсказка ввода — 3), и поле прыгает ровно в тот момент, когда игрок начинает нажимать. Замер: «Проложи дорогу», уровень 20, 360×640 — клетка 45 px на показе и 42 px на вводе. Крайние столбцы при этом съезжают примерно на 10 px, нижние строки — ещё больше.
   - Это и есть, скорее всего, причина промахов CDP-клика из отступления 2. У пальца та же проблема: игрок целится в клетку, а поле под ним уменьшается.
   - Нужно, чтобы размер клетки за партию не зависел от текста подсказки. Например:
     - у `.game-hint` фиксированная высота на 3 строки (`min-height`, при переполнении — обрезка многоточием);
     - или подсказка поверх нижнего края зоны, а не в потоке.
   - После этого верни в e2e обычный `locator(...).click()` внутри `mainScreen(page)` вместо `evaluate(el => el.click())`. Если клик всё равно промахивается — разбирайся с причиной и опиши в отчёте, а не обходи её.
   - Проверка: e2e, который на одном поле (уровень 20, 360×640) сравнивает ширину `.gcell` на `preview` и `input` — должна совпасть.
4. **Вибрация (ТЗ §7.2: «нет второй вибрации, если `note` есть»).**
   - В тестах нет случая, когда `wrong` появляется в том же кадре, что и `note`. Сейчас второй `rerender` с `note` идёт на тот же `review`, где число `wrong` не изменилось, так что тест прошёл бы и без проверки `note`. Нужен тест `input` → `review` с `note: "❌ …"` → вибраций нет — для матрицы, поездки и дороги (можно одним тестом на `useFrameVibration` в `common.test.tsx`).
   - `useFrameVibration` начинает с `{done: false, wrong: 0}`, поэтому если Mini App открыли посреди `review` или `done` (переподключение, повторный вход), телефон вибрирует на первом же кадре. Начальное значение бери из первого кадра (`useRef({done, wrong: wrongCount})`), вибрация — только на изменение. Тест: первый рендер сразу `done` → вибраций нет.
5. **Таймер матрицы (ТЗ §3) — желательно.** `TimerBar` перерисовывает компонент 60 раз в секунду всё время, пока открыта матрица, в том числе на отсчёте, разборе и в overtime. На слабом телефоне это лишний расход батареи. Проще и дешевле CSS: при новом `left` поставить ширину `left/total` без перехода, затем перевести её в 0 с `transition: width <left>s linear`. В overtime — 0 без анимации.
