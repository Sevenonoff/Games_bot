# Отчёт M4. Морской бой в Mini App

Черновик — исполнитель (ветка `miniapp/m4-sea-wip`, коммит `b7f3607` от `main` = `850a05b`). Доведение до сдачи, приёмка и вливание — Claude (ветка `miniapp/m4-sea`). Отдельной приёмки со стороны не было: доделывал и проверял один и тот же исполнитель.

## 1. По пунктам ТЗ

### §1. Подключение
Сделано. `src/games/sea/{Sea.tsx, Sea.css, geometry.ts}`, строка `sea` в `registry.ts`. Корень — `<div class="game game-sea" data-status data-turn>`. Каркас, протокол и сервер не тронуты. В `tests/unit/app.test.tsx` тест заглушки «скоро» теперь временно убирает `sea` из реестра: видов без компонента больше нет.

### §2. Сервер решает
Сделано. Payload'ы — из `view.actions` с подстановкой `{r}`, `{c}`, `{o}`. У клеток выстрела есть `data-payload`. Кнопки действий («Сначала», «Готов», «Сдаться», «Отменить приглашение», кнопки итога, «Меню») и их подписи берутся из `screen.rows`. Свои подписи клиента — только из списка ТЗ.

### §3. Бой
Сделано: два поля 8×7, своё ≈60%, рядом на ширине больше 700 px; клетки `sea`/`miss`/`hit`/`sunk`/`ship`; строка состояния; кольцо таймера с плавным убыванием; пропуски; две последние строки ходов; выстрел только в свой ход по воде; мигание по кадрам сервера; карточка итога с причиной, очками, рейтингом и строками пути; сдача через `showConfirm`, без Telegram — `window.confirm`.

Иначе: «Отменить приглашение» до начала боя (`placing`) тоже спрашивает подтверждение («Отменить партию?»). ТЗ этого не требует, но отмена необратима.

### §4. Расстановка
Сделано: док от большого к малому, перетаскивание на pointer events, зелёная/красная тень (только подсказка), `place` с центром по правилу ядра `(size−1)//2` и ориентацией, автоматический `fix` после кадра с `current`, возврат в док с анимацией после ошибки или броска мимо поля, «Повернуть», таймер расстановки между редкими кадрами, `waiting_ready`.

Иначе: тень рисуется на клетках поля, а не отдельным кораблём под пальцем. Под пальцем её закрывает сам палец, но на соседних клетках видно, куда встанет корабль.

### §5. Приглашение
Сделано: код крупно, «Отправить другу» (share-ссылка через `openTelegramLink`), «Скопировать код» с надписью «Скопировано», «Отменить приглашение» из `screen.rows`.

### §6. Вибрация
Сделано, по разнице кадров, один раз на событие: свой удачный выстрел — `medium`, попадание по своему кораблю — `heavy`, победа — `success`, поражение — `error`.

## 2. Исправлено при доведении черновика

1. **Итог показывал старое поле из кнопок.** В кнопки итога попадали все кнопки экрана, включая 56 клеток старого поля (`data: "noop"`) и второе «Меню». Карточка висела над сеткой эмодзи, поля боя сжимались до нуля. Теперь `noop` и `menu` из этого списка исключены, есть тест.
2. **`place` уходил дважды на одно отпускание.** Обработчики `pointerup` стояли и на сетке, и на `window`, оба видели одно состояние перетаскивания. По логу dev-сервера в e2e расстановки было 12 `mpp` на 6 кораблей. Оставлены только слушатели на `window`. В jsdom это не воспроизводится: Preact не вешает там `onPointerUp` на элемент. Поэтому проверка — по логу e2e (6 `mpp` на 6 кораблей).
3. **Поле расстановки было узким:** клетка всегда 30 px. Теперь размер считается по ширине экрана и оставшейся высоте (док и кнопки должны влезть), от 24 до 56 px.
4. **Размер полей боя после расстановки не пересчитывался.** Зона боя измерялась один раз при монтировании компонента. Если партия начиналась с расстановки, клетки считались от размера по умолчанию 360×420. Теперь — ref-колбэк с `ResizeObserver` (`useSize`).
5. **Одинаковые ключи в доке** (`key={size}` у двух кораблей размера 2 или 1) — теперь `size-index`.
6. **e2e «бой с другом» падал во всех проектах:** искал `.game-sea` внутри `mainScreen()`, а это один и тот же элемент. Исправлено.
7. Удалён отладочный `miniapp/probe-sea.mjs`.

## 3. §8. Критерии приёмки

1. `npm run build` — без ошибок TS. Бандл **21,75 КБ gzip** (JS 17,79 + CSS 3,53 + html 0,43), лимит 90.
2. vitest — **147 тестов в 11 файлах, зелёные**; из них по бою 43 (`sea.test.tsx` 32, `sea-geometry.test.tsx` 11). Образцы всех `fixtures/sea-*.json` со снимками DOM; выстрел; неактивное поле в чужой ход и после итога; кнопки из `screen.rows` (нет «Готов» в `sea-placement`, итог без `noop`); перетаскивание для кораблей 1–4 в обеих ориентациях — клетки тени и `place` с центром по ядру ровно один раз; `fix` после `current`; после ошибки нет `fix` и корабль возвращается в док; бросок мимо поля; `showConfirm`; вибрация один раз на событие.
3. Playwright — **92 passed (14,4 мин), весь набор: каркас, M3 и бой**, 4 проекта, в один поток (`E2E_WORKERS=1`: на сервере разработки 2 ГБ RAM). Бой — 16 тестов (4 × 4): с компьютером до победы через `dbg:sea_end`, обычный бой с ответом компьютера, ручная расстановка перетаскиванием полного набора (в логе dev-сервера 24 `mpp` на 4 × 6 кораблей — без дублей), бой с другом в двух окнах со сдачей. `--repeat-each=2` не гонялся — по памяти машины.
4. На 360×640 строка состояния и оба поля боя видны без прокрутки (скриншот `sea-03-battle`).
5. `.venv/bin/python -m pytest` после вливания в `main` — **704 passed, 1 skipped**; на объединённом `main` также `npm run build` и 147 vitest — зелёные.
6. Без `any` и `console.log` в новых файлах; геометрия — чистые функции с тестами; комментарии по-русски.
