## 1. Общее для всех игр

### 1.1. Подключение и файлы
- Компонент `src/games/<kind>/<Kind>.tsx` (`memo/Memo.tsx`, `matrix/Matrix.tsx`, `tower/Tower.tsx`, `path/Path.tsx`) и одна строка в `src/games/registry.ts`. Компонент получает `GameProps`: `view`, `screen`, `press`, `note`, `tg`.
- Общие части четырёх игр — в `src/games/common/`, а не копией в каждой игре:
  - шапка;
  - поле с подбором размера клетки;
  - полоска таймера;
  - нажатое состояние клетки;
  - подстановка `{r}`/`{c}` в шаблон.
- CSS — файл рядом с компонентом (`Memo.css` и т.п., импорт из компонента) на переменных темы каркаса (`--bg`, `--text`, `--hint`, `--button`, `--secondary-bg` из `app.css`). Каркас (`src/app/`, `src/main.tsx`, `src/connection.ts`, `src/protocol.ts`) не менять. Нужна правка каркаса — вопрос в отчёте.
- Корневой элемент экрана игры: `<div class="game game-<kind>" data-phase={phase}>`. У мемо `data-phase` — `"play"` или `"done"`. Класс `game` нужен e2e-помощнику `mainScreen()`, `data-phase` — тестам, чтобы ждать нужную фазу.

### 1.2. Сервер решает
- **Правила на клиенте не повторяются.** Клиент не знает, какая клетка верная, и не меняет поле до ответа сервера. Одно исключение — ради отклика: нажатая клетка сразу получает класс `pressed` на 150 мс, а итоговый вид приходит кадром сервера.
- Payload'ы — **только** из шаблонов `view.actions`:
  - нажатие клетки — `actions.tap` с подставленными `{r}`, `{c}`;
  - на фазах `done`/`review` нажатие любой клетки — `actions.skip`;
  - «Закончить» — `actions.quit`.
  Подпись кнопки «Закончить» берётся из `screen.rows` (кнопка с `data == actions.quit`).
- Каждая клетка-кнопка несёт `data-payload` — ровно ту строку, которую она пошлёт. По нему e2e нажимает клетку из `/dev/hint`.
- Фазы и таймеры переключает сервер кадрами (`push`). Клиент не ведёт своих таймеров фаз. Исключение — плавная полоска таймера матрицы (§3).

### 1.3. Вид
- Шапка (закреплена сверху):
  - название и уровень;
  - очки, серия (`combo`);
  - справа — таймер (матрица), «Раунд N из M» (поездка, дорога) или «Ходы» (мемо).
- Подсказка фазы (`view.hint`) — под полем. Текст экрана (`screen.text`) в игре не показывается: всё берётся из `view`.
- Поле — CSS-grid `grid.rows × grid.cols`, клетки квадратные.
  - Размер клетки — наибольший, при котором поле влезает в ширину экрана минус 16 px и в высоту между шапкой и кнопкой «Закончить».
  - Самое большое поле — **14 строк × 7 столбцов** (уровни 40+ у мемо, матрицы, дороги; 80+ у поездки).
  - На 360×640 оно обязано влезать без горизонтальной прокрутки. Если клетка выходит меньше 30 px — поле прокручивается по вертикали, а шапка остаётся на месте.
- Анимации — CSS (transform/opacity), 120–250 мс. При `prefers-reduced-motion: reduce` переходы мгновенные (в `app.css` это уже включено глобально).

### 1.4. Вибрация (через `props.tg`, если он не `null`)
Каркас уже вибрирует: `selectionChanged()` на каждое нажатие, а на `note` — `notificationOccurred("error")`, если в нём «❌», иначе `impactOccurred("light")`. Игра добавляет только то, чего у каркаса нет:
- переход кадра в фазу `done` (раунд или поле пройдены) — `notificationOccurred("success")`;
- в новом кадре появилась клетка `wrong`, а `note` пуст — `notificationOccurred("error")`.

### 1.5. Что остаётся каркасу
- Итог партии — экран без `view`, его рисует универсальный рендер.
- Уведомления `note` показывает toast каркаса.
- Карточки `notice` выводит каркас.

## 2. Мемо (`memo`)

Образцы: `memo-play`, `memo-mismatch`, `memo-done`.

- Карты:
  - рубашка (`back`) — единый узор на `--secondary-bg`;
  - открытая (`face`) — переворот по оси Y за 200 мс, эмодзи `v` крупно (≈60% клетки);
  - найденная (`matched`) — эмодзи остаётся, карта бледнеет до 50% и чуть уменьшается.
- Несовпавшая пара закрывается кадром сервера через 3 с или раньше — следующим нажатием. Закрытие — обратный переворот.
- Шапка: «Пары 3/8» (`pairs`), «Ходы 9 из 16» (`moves`; красным, если `made > limit`), очки, серия.
- `done: true` — все карты коротко подпрыгивают (400 мс), подсказка из `hint`; нажатие любой карты — `skip`.

## 3. Матрица памяти (`matrix`)

Образцы: `matrix-countdown`, `-preview`, `-input`, `-done`, `-review`.

- Фазы:
  - `countdown` — крупная цифра `countdown` поверх затемнённого поля;
  - `preview` — синие клетки (`shown`) появляются разом;
  - `input` — все скрыты, найденные становятся синими;
  - `review` — `answer` зелёные, `wrong` красные с ❌;
  - `done` — все синие, лёгкая пульсация.
- Таймер — полоска во всю ширину под шапкой, `timer.left / timer.total`; при ≤ 10 с она красная.
  - Кадры с таймером приходят раз в 5 с. Между ними клиент **плавно уменьшает полоску сам** от последнего `left`, но число секунд показывает только из кадра.
  - `overtime: true` — полоска пустая, подсказка сервера (`hint`) говорит, что делать.

## 4. Поездка на числах (`tower`)

Образцы: `tower-countdown`, `-preview`, `-input`, `-review`.

- Клетки:
  - `inactive` — жёлтая, без числа (правило пользователя: всегда жёлтые);
  - `hidden` — белая, с рубашкой;
  - `number` — белая, с числом `v`;
  - `wrong` — красная, в углу правильное число `v` (если есть).
- Над полем — дорога: полоса с финишем 🏁 слева и машинкой 🚗, которая едет справа налево. Положение — `extra.road` (0..1), переезд — анимация 400 мс. Под дорогой — «Проехали N км» (`extra.km`).
- «Раунд N из M» (`rounds`) вместо таймера. `countdown` — как у матрицы.

## 5. Проложи дорогу (`path`)

Образцы: `path-countdown`, `-preview`, `-input`, `-done`, `-review`.

- `preview`: видны человек (`person`, эмодзи `v`), дом (`house`), препятствия ⛔ (`block`).
- `input`: сервер присылает только клетки дороги игрока (`step`) — по ним рисуется линия между соседними клетками (SVG поверх grid). **Препятствия и концы с показа клиент не запоминает.**
- `review`:
  - препятствия;
  - ❌ на ошибке;
  - кратчайшая дорога (`answer`) — пунктиром поверх.
- `done`: поле открыто, дорога игрока — сплошной линией.
- Уведомление «🎯 Кратчайшая дорога! +N» приходит в `note`, его показывает обычный toast каркаса.

## 6. Не входит
- изменения правил, уровней, времени показа (всё на сервере);
- карточка итога партии;
- звуки;
- правки каркаса и сервера.

## 7. Тесты и критерии приёмки

1. **Сборка.** `npm run build` без ошибок TS (`strict`), бандл без картинок ≤ 90 КБ gzip (каркас ≈ 14).
2. **vitest** (`tests/unit/<kind>.test.tsx`) для каждой игры:
   - все её образцы из `docs/miniapp/fixtures/` рендерятся без ошибок;
   - снимки DOM (`toMatchSnapshot`), осмысленные, не пустые;
   - нажатие клетки вызывает `press` с payload из шаблона (`{r}`/`{c}` подставлены);
   - на `done`/`review` — `skip`;
   - «Закончить» — `quit`;
   - вибрация по §1.4 (фейковый `tg`): `success` при переходе в `done`, `error` при новой `wrong` без `note` и **нет** второй вибрации, если `note` есть.
3. **Playwright** (`tests/e2e/<kind>.spec.ts`) против dev-сервера, 4 проекта (360/414 × светлая/тёмная):
   - Полная партия от меню до итога: ходы по `hint(user)` (`GET /dev/hint`), клик по `button[data-payload="…"]` внутри `mainScreen(page)`. Перед ходом ждать `data-phase="input"` (у мемо — `play`). На `done` подсказка возвращает `skip`. На `countdown`, `preview` и `review` она возвращает `null`: дождаться следующей фазы (сервер переключит сам) или нажать любую клетку (`skip`).
   - Ещё одна партия — с ошибкой и разбором (у мемо — несовпавшая пара). Чтобы ошибиться, нажать клетку, чей payload **не равен** подсказке.
   - Самое большое поле: админ `serverPress(page, admin, "dbg:level:<kind>:40")` (для `tower` — `80`) до начала партии. Поле 14×7 на 360×640 без горизонтальной прокрутки (`scrollWidth <= clientWidth`), скриншот.
   - Нет утечек: 10 партий мемо подряд («Мемо» → «Закончить» → «🔁 Ещё раз»). Число узлов `document.querySelectorAll('*').length` на экране партии в последний раз не больше, чем в первый, плюс 10%.
   - Скриншоты каждой фазы в `tests/e2e/__screenshots__/`.
   - id игроков: свои базы из диапазона **200–299**, через `userId(base, project)`; админы — **300–399** (`300 + номер проекта` и т.п.). Пересечений между тестами нет.
4. **Существующие тесты каркаса** (52 vitest, 20 e2e) остаются зелёными. `.venv/bin/python -m pytest` не трогается и зелёный.
5. **Код:**
   - без `any`;
   - без `console.log`;
   - без копий общих частей между играми;
   - комментарии по-русски там, где неочевидно «почему».
