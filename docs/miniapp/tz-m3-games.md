# ТЗ M3. Экраны игр с уровнями: Мемо, Матрица памяти, Поездка на числах, Проложи дорогу

Исполнитель: **другая модель**. Приёмка: Claude по `acceptance.md`.
Можно отдавать по одной игре: M3a — Мемо, M3b — Матрица, M3c — Поездка на числах, M3d — Проложи дорогу. Каждая — отдельная ветка и сдача.
Перед началом прочитать: `README.md`, `tz-m1-core.md` §3.1–3.2 (схемы `view`), `tz-m2-shell.md` §3.7 (как подключить компонент). Образцы состояний — `docs/miniapp/fixtures/<игра>-*.json`.

## 1. Общие требования ко всем играм

- Компонент `src/games/<kind>/<Kind>.tsx` регистрируется в `src/games/registry.ts` и получает `GameProps` (`view`, `screen`, `press`, `note`).
- **Правила на клиенте не повторяются.** Клиент не знает, какая клетка верная, и не меняет поле до ответа сервера. Есть одно исключение ради отклика: нажатая клетка сразу получает класс `pressed` (нажатое состояние, 150 мс), а итоговый вид приходит с сервера (обычно через 50–150 мс).
- Нажатие клетки: `press(view.actions.tap.replace("{r}", r).replace("{c}", c))`. На фазах `done`/`review` — `press(view.actions.skip)`. «Закончить» — `press(view.actions.quit)`.
- Шапка: название и уровень, очки, серия (`combo`), таймер или «Раунд N из M». Подсказка фазы (`hint`) — под полем.
- Поле — CSS-grid по `grid.rows × grid.cols`, клетки квадратные. Поле вписывается в ширину экрана минус 16 px и в высоту, оставшуюся под шапкой; клетка не меньше 32 px. Если не влезает — поле прокручивается, шапка закреплена.
- Анимации — CSS (transform/opacity), 120–250 мс. При `prefers-reduced-motion` переходы мгновенные.
- Вибрация: верное нажатие — `impactOccurred("light")`, ошибка (`note` с «❌» или клетка `wrong` в новом кадре) — `notificationOccurred("error")`, раунд пройден — `notificationOccurred("success")`.
- Текст экрана (`screen.text`) в игре не показывается, всё берётся из `view`. Кнопки экрана, кроме клеток поля, — внизу: «Закончить».
- Итог партии приходит экраном без `view` и рисуется универсальным рендером M2. Отдельная карточка итога — не в этом ТЗ.

## 2. Мемо (M3a)

- Карты рубашкой вверх (`back`): единый узор на `--secondary-bg`. Открытая (`face`) — переворот по оси Y, 200 мс, эмодзи `v` крупно (60% клетки). Найденная (`matched`) — эмодзи остаётся, карта бледнеет до 50% и чуть уменьшается.
- Несовпавшая пара закрывается кадром с сервера через 3 с или раньше — следующим нажатием. Закрытие — обратный переворот.
- Шапка: «Пары 3/8», «Ходы 9 из 16» (красным, если сделано больше лимита), очки, серия.
- `done: true` — короткая анимация (все карты подпрыгивают, 400 мс), подсказка «Нажмите любую карту»; нажатие — `skip`.

## 3. Матрица памяти (M3b)

- Фазы: `countdown` — крупная цифра поверх затемнённого поля; `preview` — синие клетки (`shown`) появляются разом; `input` — все скрыты, найденные становятся синими; `review` — `answer` зелёные, `wrong` красные с ❌; `done` — все синие, лёгкая пульсация.
- Таймер: полоска во всю ширину под шапкой, `left/total`, цвет меняется на красный при ≤ 10 с. Между кадрами сервера (раз в 5 с) клиент **плавно уменьшает полоску сам** от последнего `left`, но число секунд берёт только из кадра. `overtime: true` — полоска пустая, надпись «Время вышло — закончите раунд».

## 4. Поездка на числах (M3c)

- `inactive` — жёлтая неактивная клетка без числа (правило пользователя: всегда жёлтые). `hidden` — белая с рубашкой. `number` — белая с числом. `wrong` — красная, в углу правильное число (`v`).
- Над полем — дорога: полоса с финишем 🏁 слева и машинкой 🚗, которая едет справа налево. Положение — `extra.road` (0..1), переезд — анимация 400 мс. Под дорогой — «Проехали N км» (`extra.km`).
- «Раунд N из 6» вместо таймера.

## 5. Проложи дорогу (M3d)

- Показ (`preview`, 1 с): видны человек (`person`, эмодзи `v`), дом (`house`), препятствия ⛔ (`block`). Затем поле скрывается: видны только клетки дороги игрока (`step`) — по ним рисуется линия между соседними клетками.
- Во время ввода сервер не присылает препятствия и концы — клиент не должен их «помнить» с показа.
- `review`: препятствия, ❌ на ошибке, кратчайшая дорога 🟡 (`answer`) — пунктиром поверх. `done`: поле открыто, дорога игрока — сплошной линией.
- Уведомление «🎯 Кратчайшая дорога! +N» — крупно над полем на 1,5 с вместо обычного toast.

## 6. Не входит
Изменения правил, уровней и времени показа (всё на сервере); карточка итога; звуки.

## 7. Тесты и критерии приёмки (для каждой игры)
1. vitest: компонент рендерит все образцы `fixtures/<игра>-*.json` без ошибок; снимок DOM каждого образца (`toMatchSnapshot`); нажатие клетки вызывает `press` с правильным payload из шаблона; на `done`/`review` — `skip`.
2. Playwright против dev-сервера M1: полная партия игры от меню до итога. Ходы делаются по подсказке сервера: в dev-режиме M1 отдаёт `GET /dev/hint` — верную клетку текущей партии, только при `MINIAPP_DEV=1`. Ещё одна партия — с ошибкой и разбором. Скриншоты каждой фазы на 360×640 и 414×896, светлая и тёмная тема.
3. Поле 7×14 (самые большие уровни) влезает на 360×640 без горизонтальной прокрутки. Проверка — e2e с `/dbg level <игра> 40` через dev-вход админа.
4. Нет утечек: после 20 партий подряд число DOM-узлов и слушателей не растёт (e2e, `performance.memory` не нужен — считать `document.querySelectorAll('*').length`).
5. Сдача: ветка `miniapp/m3<буква>-<игра>`, отчёт по §1–5 с отступлениями, скриншоты, вывод тестов.
