# Задача M4 для исполнителя: морской бой в Mini App

Это поручение целиком, его можно отдать модели-исполнителю как есть. Техническое задание — `docs/miniapp/tz-m4-seafight.md`. Здесь — как к нему подступиться, что можно и что нельзя, как сдавать.

---

## Кто ты и что делаешь

Ты делаешь экран морского боя в Telegram Mini App бота развивающих игр: бой с компьютером и с другом, оба поля, расстановка кораблей перетаскиванием, мигание потопленного корабля, итог.

Сервер и каркас фронтенда уже готовы. Сейчас партия показывается «старым» полем из кнопок с плашкой «скоро». Твоя задача — красивый экран по `view`.

Правил на клиенте нет и не будет. Клиент не знает, где корабли соперника и можно ли ставить корабль в клетку. Он рисует `view` и шлёт нажатия по шаблонам из `view.actions`.

Параллельно другой исполнитель может делать экраны игр с уровнями (M3) в `src/games/{memo,…,common}/`. Вы пересекаетесь только в одной строке `src/games/registry.ts`, конфликт в ней решит принимающий. Общие части M3 тебе не нужны, у боя свой вид.

## Порядок работы
1. Бой: поля, выстрел, статус, мигание, итог.
2. Приглашение и ожидание.
3. Расстановка перетаскиванием — самая трудная часть.

Геометрию корабля (клетки по началу или центру и ориентации, центр по правилу ядра, проверка «за краем, на занятом, на запрещённом») и перевод координат указателя в клетку сделай чистыми функциями в `src/games/sea/` с юнит-тестами, отдельно от компонента.

## Окружение
- Node 22, Python-окружение `.venv` в корне репозитория для dev-сервера. Как на macOS, так и на сервере разработки — см. `docs/miniapp/cleanup.md`, раздел «Особенности машин».
- Dev-сервер `miniapp/dev-server.sh`:
  - порт 8448; если занят — задать `E2E_PORT` для e2e;
  - своя БД, Telegram не трогает;
  - вход `?dev_user=<id>&dev_name=<имя>` только с localhost;
  - ссылка-приглашение для второго игрока — параметр `&start=mp_<код>`;
  - компьютер «думает» 1 с перед ходом.
- **Не запускай** боевого бота (`sea_fight_aiogram/main.py`, `run.py`) и не трогай сервис `games-tg-bot`.
- `npm run e2e` сам собирает приложение и поднимает dev-сервер на свежей БД.
  - Параллельных браузеров по умолчанию — половина ядер; больше — `E2E_WORKERS=4`, если машина тянет.
  - На Linux-сервере: `LD_LIBRARY_PATH=$HOME/.local/lib/playwright-deps npm run e2e`.
- Отладка: админы dev-сервера в e2e — id **500–599** (`DEV_ADMINS` уже настроен).
  - `serverPress(page, 500 + n, "dbg:sea_end:reduced")` создаёт бой с компьютером за выстрел до победы.
  - Затем в окне: «Морской бой» → «⚔️ Вернуться к партии».

## Ветка
`git switch -c miniapp/m4-seafight` от `main` (коммит с этим файлом или новее). Коммить по ходу работы осмысленными шагами. В конце ветка должна собираться и проходить тесты. Сдать — `git push` ветки на GitHub.

## Можно / нельзя
- Можно:
  - `miniapp/src/games/sea/…`;
  - строка `sea` в `miniapp/src/games/registry.ts`;
  - `miniapp/tests/unit/sea*.test.tsx` и снимки к ним;
  - `miniapp/tests/e2e/sea*.spec.ts`;
  - отчёт `docs/miniapp/reports/m4-seafight.md`.
- **Нельзя** без согласования:
  - каркас: `miniapp/src/app/`, `main.tsx`, `connection.ts`, `protocol.ts`, `telegram.d.ts`, `Placeholder.tsx`;
  - `miniapp/tests/e2e/fake-telegram.ts`, `playwright.config.ts`, `vite.config.ts`, `package.json` (новых зависимостей нет: перетаскивание — на pointer events без библиотек);
  - сервер: `games_core/`, `sea_fight_aiogram/`, `max_bot/`, `tests/` (питоновские);
  - `docs/miniapp/` (кроме отчёта);
  - чужие `src/games/{memo,matrix,tower,path,common}/`.
  Если нужно что-то из этого (поле в `view`, помощник e2e, правка каркаса), опиши в отчёте, сам не исправляй. Свой локальный помощник можно положить в свой spec-файл.
- Подписи кнопок действий берутся из `screen.rows` (ТЗ §2). Свои подписи клиента — только те, что перечислены в ТЗ §2. Весь текст — по-русски.
- Комментарии в коде — по-русски, имена — по-английски. TypeScript `strict`, без `any`.

## Что сдать
1. Ветку `miniapp/m4-seafight` на GitHub. Из `miniapp/` с нуля проходят `npm ci && npm run build && npm test && npm run e2e`, а также `npx playwright test --repeat-each=2`.
2. Отчёт `docs/miniapp/reports/m4-seafight.md`:
   - по каждому пункту ТЗ §1–6 и §8 — «сделано / не сделано / сделано иначе — почему»;
   - отступления от ТЗ и найденные проблемы сервера или протокола;
   - размер бандла (gzip) и хвосты команд выше;
   - список скриншотов. Сами файлы — в `miniapp/tests/e2e/__screenshots__/`, в git их не клади.
3. Ничего не выкладывай и не перезапускай на сервере.

## На что обратят внимание при приёмке
- Клиент не знает правил:
  - payload'ы только из `view.actions` (атрибут `data-payload` у клеток);
  - наличие и подписи кнопок — из `screen.rows`;
  - зелёная или красная тень при перетаскивании — только подсказка, решает ответ сервера.
- Центр и ориентация при `place` — ровно по правилу ядра, для кораблей 1–4 клеток в обеих ориентациях.
- Ошибка расстановки возвращает корабль в док. Двойного `fix` нет.
- Во время боя оба поля 8×7 и строка состояния помещаются на 360×640 без прокрутки.
- Сдача — только после подтверждения.
- Тёмная тема читается. Быстрые нажатия подряд не ломают экран.
- e2e изолированы: свои id из 400–499 и 500–599, кнопки ищутся внутри `mainScreen(page)`, тесты зелёные при повторах.

Вопросы и спорные места — в отчёт. Если что-то в ТЗ мешает сделать хорошо, предложи, как лучше, а сделай по ТЗ, пока не согласовано.
