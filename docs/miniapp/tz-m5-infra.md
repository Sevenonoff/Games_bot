# ТЗ M5. Хостинг, кнопка Mini App, выкладка

Исполнитель: **Claude**; выбор варианта хостинга и домена — **за пользователем** (отложено им до этого этапа).

## 1. Что нужно
- Публичный HTTPS-адрес с действующим сертификатом и WebSocket (Telegram открывает Mini App только по HTTPS).
- Запросы с него приходят на `127.0.0.1:8447` этой машины (89.125.106.7), где работает `games-tg-bot` с данными TG-игроков.
- Ограничения машины: нет sudo (порты 80/443 не занять, системный Caddy/nginx не поставить), есть systemd `--user` и linger.

## 2. Варианты (решает пользователь)

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| **A. Cloudflare Tunnel** | `cloudflared` (бинарник, без sudo) как `systemd --user`, именованный туннель на поддомен вроде `games.<домен>` | Без открытых портов и без sudo, сертификат и WebSocket — у Cloudflare, бесплатно | Нужен домен, делегированный в Cloudflare. Доступность Cloudflare из РФ местами нестабильна |
| **B. Caddy на RU-сервере** (china-drom, 91.227.18.215) | Поддомен на этом сервере; Caddy в Docker проксирует на 89.125.106.7:8447 (порт открыть только для IP сервера, если хостер позволит) или через обратный SSH-туннель отсюда туда (`ssh -R`, autossh как `systemd --user`) | Сервер в РФ, Caddy и сертификаты уже работают | Сервер тесный (2 ГБ RAM, диск 86%), общий с сайтом. Лишний хоп. Проверить, что сервер достаёт до этой машины |
| **C. Caddy на этой машине на высоком порту** | Caddy бинарником без sudo на `:8443`, сертификат по DNS-01 (нужен API-токен DNS-провайдера) | Один хоп, всё под нашим контролем | Адрес с портом `https://games.<домен>:8443/app/` (Telegram такое принимает), но порт должен быть открыт у хостера; нужен DNS с API |

Рекомендация Claude: **A**, если у пользователя есть домен в Cloudflare или его не жалко туда перенести; иначе **B** через обратный SSH-туннель. Решение и домен — до начала M5.

## 3. Работы
1. Поднять выбранный вариант; `systemd --user` юниты в `sea_fight_aiogram/deploy/` (как `games-tg-bot.service`), включая автоперезапуск.
2. Проверка снаружи: `curl -I https://<адрес>/app/` → 200, WebSocket `wss://<адрес>/ws` проходит `hello` в dev-режиме **на тестовом порту**, не в проде.
3. BotFather: `/newapp` для `@games_telegram_robot` (short name, например `games`), URL `https://<адрес>/app/`. Кнопка меню бота (`setChatMenuButton`, тип `web_app`) — «🎮 Играть». Это действия в аккаунте пользователя: Claude готовит точные шаги, пользователь выполняет или подтверждает.
4. В меню чат-бота — кнопка «📱 Открыть приложение» (кнопка типа `web_app`, только в Telegram; в Max её нет). Для этого в `Button` ядра нужен признак ссылки на Mini App. Это небольшое изменение M1, согласуется отдельно.
5. `MINIAPP_SHORT_NAME` в `.env` → ссылки-приглашения из Mini App ведут в Mini App (`tz-m1-core.md` §2.5).
6. Сборка фронтенда при выкладке: `cd miniapp && npm ci && npm run build`; бот отдаёт `miniapp/dist`. Рестарт `games-tg-bot` — по команде пользователя.
7. Наблюдение: в `logs/tg_bot.log` строки `ws open/close user=… ms=…` и `tap … via=web`; ошибки проверки `initData` — отдельной строкой без самих данных.

## 4. Готово, когда
Mini App открывается кнопкой меню бота у пользователя и у второго аккаунта; бой Mini App ↔ чат доходит до конца; после рестарта бота открытый Mini App переподключается сам.
