# Задача M3 для исполнителя: экраны игр с уровнями

Это поручение целиком: его можно отдать модели-исполнителю как есть. Техническое задание — `docs/miniapp/tz-m3-games.md`. Здесь — как к нему подступиться, что можно и что нельзя, как сдавать.

---

## Кто ты и что делаешь

Ты делаешь экраны четырёх игр в Telegram Mini App бота развивающих игр:
- 🃏 Мемо;
- 🟦 Матрица памяти;
- 🚗 Поездка на числах;
- 🏡 Проложи дорогу.

Сервер и каркас фронтенда готовы. Сейчас партия этих игр показывается «старым» полем из кнопок с плашкой «скоро». Твоя задача — красивые экраны по `view`.

Правил игр на клиенте нет и не будет. Сервер присылает состояние (`view`), клиент рисует его и шлёт нажатия по шаблонам из `view.actions`.

Параллельно другой исполнитель может делать морской бой (M4) в `src/games/sea/`. Вы не пересекаетесь, кроме одной строки в `src/games/registry.ts`, а конфликт в ней решит принимающий.

## Прочитай до начала (по порядку)
1. `docs/miniapp/README.md` §4–5 — протокол и `view`. Это контракт, его не меняй.
2. `docs/miniapp/tz-m3-games.md` — **твоё ТЗ**, по нему принимают работу.
3. `docs/miniapp/tz-m1-core.md` §3.1–3.2 — схемы `view` этих игр.
4. Код каркаса `miniapp/src/`:
   - `games/registry.ts` (`GameProps`), `games/Placeholder.tsx`;
   - `app/App.tsx` (что каркас уже делает сам: toast, вибрация на `note`, карточки);
   - `app/app.css` (переменные темы);
   - `protocol.ts` (типы `MemoView` … `PathView`).
5. `miniapp/tests/e2e/fake-telegram.ts` — готовые помощники e2e: `openApp`, `mainScreen`, `hint`, `serverPress`, `dismissNotices`, `userId`, `shot`.
6. `docs/miniapp/fixtures/{memo,matrix,tower,path}-*.json` — настоящие кадры сервера каждой фазы. По ним удобно верстать и писать юнит-тесты без сервера.
7. `docs/miniapp/acceptance.md` и `docs/miniapp/reviews/m2-shell-1.md` — как проверяют и на чём споткнулся M2.

## Порядок работы
Игры по одной, каждая — отдельными коммитами: **Мемо → Матрица → Поездка → Дорога**. Общие части (шапка, поле с подбором размера клетки, полоска таймера, нажатое состояние клетки) вынеси в `src/games/common/` уже на мемо и переиспользуй дальше.

## Окружение
- Node 22, Python-окружение `.venv` в корне репозитория для dev-сервера. Как на macOS, так и на сервере разработки — см. `docs/miniapp/cleanup.md`, раздел «Особенности машин».
- Dev-сервер: `miniapp/dev-server.sh`:
  - порт 8448 (если занят — `E2E_PORT` для e2e);
  - своя БД;
  - Telegram не трогает;
  - вход `?dev_user=<id>&dev_name=<имя>` только с localhost.
- **Не запускай** боевого бота (`sea_fight_aiogram/main.py`, `run.py`) и не трогай сервис `games-tg-bot`.
- `npm run e2e` сам собирает приложение и поднимает dev-сервер на свежей БД.
  - Число параллельных браузеров по умолчанию — половина ядер. Больше — `E2E_WORKERS=4`, если машина тянет.
  - На Linux-сервере: `LD_LIBRARY_PATH=$HOME/.local/lib/playwright-deps npm run e2e`.
- Отладка: админы dev-сервера в e2e — id **300–399** (`DEV_ADMINS` уже настроен).
  - `serverPress(page, 300 + n, "dbg:level:matrix:40")` выставляет уровень до начала партии.
  - Остальные команды — `games_core/debug.py`, `HELP`.

## Ветка
`git switch -c miniapp/m3-games` от `main` (коммит с этим файлом или новее). Коммить по ходу работы осмысленными шагами. В конце ветка должна собираться и проходить тесты. Сдать — `git push` ветки на GitHub.

## Можно / нельзя
- Можно:
  - `miniapp/src/games/{memo,matrix,tower,path,common}/…`;
  - строки своих игр в `miniapp/src/games/registry.ts`;
  - `miniapp/tests/unit/{memo,matrix,tower,path,common}*.test.tsx` и снимки к ним;
  - `miniapp/tests/e2e/{memo,matrix,tower,path}*.spec.ts`;
  - отчёт `docs/miniapp/reports/m3-games.md`.
- **Нельзя** без согласования:
  - каркас: `miniapp/src/app/`, `main.tsx`, `connection.ts`, `protocol.ts`, `telegram.d.ts`, `Placeholder.tsx`;
  - `miniapp/tests/e2e/fake-telegram.ts`, `playwright.config.ts`, `vite.config.ts`, `package.json` (новых зависимостей нет);
  - сервер: `games_core/`, `sea_fight_aiogram/`, `max_bot/`, `tests/` (питоновские);
  - `docs/miniapp/` (кроме отчёта);
  - чужой `src/games/sea/`.
  Нужно что-то из этого (поле в `view`, помощник e2e, правка каркаса) — опиши в отчёте, сам не исправляй. Свой локальный помощник можно положить в свой spec-файл.
- Тексты игр приходят с сервера (`view.hint`, подпись «Закончить» из `screen.rows`). Свои подписи клиента — только короткие служебные в шапке: «Пары», «Ходы», «Раунд N из M», «Проехали N км». Весь текст — по-русски.
- Комментарии в коде — по-русски, имена — по-английски. TypeScript `strict`, без `any`.

## Что сдать
1. Ветку `miniapp/m3-games` на GitHub. Из `miniapp/` с нуля проходят `npm ci && npm run build && npm test && npm run e2e`, а также `npx playwright test --repeat-each=2`.
2. Отчёт `docs/miniapp/reports/m3-games.md`:
   - по каждому пункту ТЗ §1–5 и §7 — «сделано / не сделано / сделано иначе — почему»;
   - отступления от ТЗ и найденные проблемы сервера или протокола;
   - размер бандла (gzip) и хвосты команд выше;
   - список скриншотов. Сами файлы — в `miniapp/tests/e2e/__screenshots__/`, в git их не клади.
3. Ничего не выкладывай и не перезапускай на сервере.

## На что обратят внимание при приёмке
- Клиент не знает правил: payload'ы — только из `view.actions` (у клеток — атрибут `data-payload`). Поле не меняется до кадра сервера, кроме класса `pressed`.
- Проложи дорогу: во время ввода препятствия и концы не видны, даже если они были на показе.
- Поле 14×7 на 360×640 — без горизонтальной прокрутки, клетки квадратные.
- Вибрация не дублирует каркас (ТЗ §1.4).
- Тёмная тема читается. Быстрые нажатия подряд не ломают экран.
- e2e изолированы: свои id из 200–299 и 300–399, кнопки ищутся внутри `mainScreen(page)`, тесты зелёные при повторах.

Вопросы и спорные места пиши в отчёт. Если что-то в ТЗ мешает сделать хорошо, предложи, как лучше, а сделай по ТЗ, пока это не согласовано.
