## 1. Цель и подключение

- Компонент `src/games/sea/Sea.tsx` (`view.kind == "sea"`) и одна строка в `src/games/registry.ts`. Компонент рисует все состояния партии:
  - приглашение;
  - расстановку;
  - ожидание соперника;
  - бой;
  - мигание потопленного корабля;
  - итог.
- Мастер выбора (сложность, время, набор, расстановка) и экран «Морской бой» остаются экранами без `view`, их рисует универсальный рендер M2.
- Файлы — в `src/games/sea/`: компоненты, CSS на переменных темы из `app.css`, чистые функции, например геометрия корабля.
- Каркас (`src/app/`, `main.tsx`, `connection.ts`, `protocol.ts`, `telegram.d.ts`) не менять. Если нужно что-то в каркасе — напиши вопрос в отчёте.
- Корневой элемент: `<div class="game game-sea" data-status={view.status} data-turn={view.turn ?? ""}>`. Класс `game` нужен e2e-помощнику `mainScreen()`.

## 2. Сервер решает

- Компонент не знает правил: ни где корабли соперника, ни можно ли ставить корабль в клетку. Окончательно решает сервер.
- Payload'ы — только из `view.actions`: подставить `{r}`, `{c}`, `{o}`.
- Каждая клетка-кнопка несёт `data-payload` — строку, которую пошлёт. По этому атрибуту e2e нажимает клетку из `/dev/hint`.
- **Подписи и наличие кнопок действий** («Зафиксировать», «Сначала», «Готов», «Сдаться», «Отменить приглашение», «Новая партия с компьютером», «Дальше: …», «Меню») берутся из `screen.rows`. Это кнопки, у которых `data` совпадает с одним из `actions.*`, плюс `menu` и прочие из итога.
  - Нет такой кнопки на экране — действия сейчас нет. Пример: «Готов» появляется, только когда все корабли стоят.
  - Свои подписи клиента — только «Повернуть», «Отправить другу», «Скопировать код», «Скопировано», «Ваш ход», «Ход противника», «Компьютер думает…».
- `actions.surrender` до начала боя (`placing`, `waiting_ready`) — отмена партии, в бою — сдача. Подпись в обоих случаях — с сервера.

## 3. Бой (`status: "active" | "finished"`)

Образцы: `sea-my-turn`, `sea-ai-thinking`, `sea-their-shot`, `sea-blink`, `sea-result`.

- Два поля 8×7. Сверху — поле соперника `enemy` (по нему стреляют), снизу — своё `own`, мельче (≈60% ширины). На экранах шире 700 px поля стоят рядом.
- Клетки:
  - `sea` — вода;
  - `miss` — точка;
  - `hit` — 💥;
  - `sunk` — тёмно-красная клетка с 💢;
  - `ship` — серый корабль. На своём поле видны всегда, на поле соперника — только после итога.
- Строка состояния:
  - «Ваш ход» (`turn == "me"`);
  - «Ход противника»;
  - «Компьютер думает…» (`thinking`, три точки анимацией).
- Таймер хода — кольцо вокруг индикатора (`timer.left / total`, `timer` может быть `null` — без лимита). Кадры приходят не каждую секунду, между ними кольцо плавно убывает.
- Пропуски — «Пропуски: вы 1/3 · соперник 0/3» (`timeouts`), только если не нули.
- Последние ходы (`last`) — до двух строк под строкой состояния.
- Выстрел: нажатие клетки поля соперника → `press(actions.fire)`.
  - В чужой ход и после итога клетки поля соперника неактивны.
  - Уже обстрелянные клетки тоже неактивны: это не правило, а вид — у них не `sea`.
  - Если сервер ответит `note` «Не ваш ход!», его покажет toast каркаса. На экранах игр toast — сверху, поверх верхних ≈ 40–60 px, нажатий не перехватывает. Поэтому сверху лучше строка состояния, а не клетки поля соперника.
- Мигание (`blink`): клетки `blink.cells` на поле `blink.board` рисуются по `frame` (`hit` ↔ `sunk`). Кадры шлёт сервер, клиент только рисует.
- Итог (`result` не `null`) — карточка поверх полей. На ней:
  - «🏆 Победа!» или «💀 Поражение»;
  - причина (`reason`: потоплены все корабли / пропуски / сдача);
  - очки;
  - в бою с другом — рейтинг и изменение;
  - строки пути (`journey`);
  - кнопки из `screen.rows`.
  Поле соперника после итога показывает непотопленные корабли.
- «Сдаться» в бою:
  - сначала подтверждение: `props.tg.showConfirm("Сдаться? Это поражение.", ok => ok && press(actions.surrender))`;
  - без Telegram (`tg == null`) — `window.confirm`.

## 4. Расстановка (`status: "placing"`)

Образцы: `sea-placement`, `sea-placement-current`.

- Своё поле во всю ширину. Под полем — «док»: корабли, которые ещё надо поставить (`placement.sizes` минус уже стоящие `fixed`), от большого к маленькому.
- **Перетаскивание** (pointer events, пальцем и мышью):
  - корабль берётся из дока и тащится на поле;
  - под пальцем — тень корабля;
  - тень зелёная, если место допустимо по виду: не за краем, не на клетках `fixed` и `forbidden`. Иначе тень красная. Это только подсказка.
- Отпустил на поле → `press(actions.place)` с центром и ориентацией `{o}` = `h` | `v`. Центр — как в ядре: клетка с индексом `(size-1)//2` от начала корабля (у чётных — левая или верхняя из двух средних).
- После кадра, где `placement.current` — этот корабль, а `note` без ошибки → `press(actions.fix)`.
- Ошибка (`note`, `current` не изменился) → корабль возвращается в док с анимацией.
- `placement.current` и `placement.vertical` показывают поставленный, но не зафиксированный корабль: например, после ответа на `place`. Его тоже рисуют.
- Кнопка «Повернуть» поворачивает корабль в доке до перетаскивания.
- Кнопки «Сначала» (`reset`), «Готов» (`ready`) и «Сдаться» берутся из `screen.rows`, см. §2.
- Время на расстановку — `placement.left`. Кадры с ним приходят редко, между ними клиент считает сам.
- `status: "waiting_ready"` (образец `sea-waiting-ready`): своё поле с кораблями и «Ждём соперника…».

## 5. Приглашение (`status: "waiting"`)

Образец: `sea-invite`.

На карточке:
- код крупно;
- «Отправить другу» → `tg.openTelegramLink("https://t.me/share/url?url=" + encodeURIComponent(invite.link))`;
- «Скопировать код» → буфер обмена и короткая надпись «Скопировано» рядом с кнопкой;
- «Отменить приглашение» — из `screen.rows`.

## 6. Вибрация (через `props.tg`)

Каркас уже вибрирует на каждое нажатие и на `note`. Игра добавляет только:
- попадание или потопление своим выстрелом (`last[0]` от `me`) — `impactOccurred("medium")`;
- по своему кораблю попали — `impactOccurred("heavy")`;
- победа — `notificationOccurred("success")`, поражение — `notificationOccurred("error")`.

Вибрация — по разнице между прошлым и новым кадром, один раз на событие.

## 7. Не входит

- изменения правил, алгоритма компьютера и времени хода;
- звуки;
- чат между игроками;
- правки каркаса и сервера.

## 8. Тесты и критерии приёмки

1. `npm run build` без ошибок TS (`strict`). Бандл без картинок ≤ 90 КБ gzip.
2. vitest (`tests/unit/sea*.test.tsx`):
   - все образцы `fixtures/sea-*.json` рендерятся, снимки DOM;
   - выстрел шлёт `fire` с координатами;
   - в чужой ход и после итога поле соперника неактивно;
   - кнопки действий берутся из `screen.rows`: в `sea-placement` нет «Готов»;
   - расстановка перетаскиванием (синтетические pointer events) шлёт `place` с центром по правилу ядра и нужной ориентацией — для горизонтальных и вертикальных кораблей размера 1, 2, 3, 4; после кадра с `current` — `fix`; после `note` с ошибкой корабль снова в доке;
   - «Сдаться» вызывает `showConfirm`; при `false` ничего не шлёт;
   - вибрация по §6 срабатывает один раз на событие.
3. Playwright (`tests/e2e/sea*.spec.ts`) против dev-сервера, 4 проекта:
   - **бой с компьютером до победы**:
     - админ `serverPress(page, admin, "dbg:sea_end:reduced")` создаёт партию за выстрел до победы;
     - в окне приложения: плитка «Морской бой» (`sea`) → «⚔️ Вернуться к партии» (`mpb`);
     - выстрел по `hint(admin)`;
     - итог;
     - «Новая партия с компьютером» открывает мастер;
   - **обычный бой**: мастер с компьютером (обычный, без лимита, малый, авто) → несколько выстрелов по `hint`, компьютер отвечает: дождаться `data-turn="me"`;
   - **ручная расстановка перетаскиванием полного набора** → «Готов» → бой начался (`data-status="active"`);
   - **бой с другом, два контекста браузера**:
     - первый создаёт приглашение (мастер «Играть с другом»), код берётся из экрана приглашения;
     - второй открывает `/app/?dev_user=<id>&dev_name=<имя>&start=mp_<код>`;
     - по выстрелу у каждого;
     - сдача первого → у второго карточка победы;
   - скриншоты всех состояний на 360×640 и 414×896, обе темы;
   - id игроков — **400–499**, админы — **500–599**, через `userId(base, project)`.
   Бой «Mini App против чата» проверяет Claude тестом сервера, делать его не нужно.
4. Во время боя оба поля 8×7 помещаются на 360×640 без прокрутки, на скриншоте — строка состояния и оба поля.
5. Существующие тесты каркаса (52 vitest, 20 e2e) зелёные. `.venv/bin/python -m pytest` зелёный.
6. Код:
   - без `any` и `console.log`;
   - геометрия и перетаскивание — чистыми функциями с тестами, отдельно от компонента;
   - комментарии по-русски.
