# ТЗ M4. Морской бой в Mini App: с компьютером и с другом

Исполнитель: **другая модель** (если сроки поджимают — Claude). Приёмка: Claude по `acceptance.md`.
Перед началом прочитать: `README.md`, `tz-m1-core.md` §3.3 (схема `view` боя), `tz-m2-shell.md` §3.7. Образцы — `docs/miniapp/fixtures/sea-*.json`. Правила и сценарии боя — `tests/scenarios/ai.scenario`, `tests/scenarios/mp.scenario` (читать как описание поведения).

## 1. Цель

Компонент `src/games/sea/Sea.tsx` (`view.kind == "sea"`) рисует все состояния партии: приглашение, расстановку, ожидание соперника, бой, мигание потопленного корабля, итог. Мастер выбора (сложность, время, набор, расстановка) остаётся экранами без `view` — их рисует универсальный рендер M2.

## 2. Бой (`status: "active" | "finished"`)

- Два поля 8×7. Сверху — поле соперника (по нему стреляют), снизу — своё, мельче (≈60% ширины). На широких экранах (≥ 700 px) поля стоят рядом.
- Клетки: `sea` — вода, `miss` — точка 💠, `hit` — 💥, `sunk` — тёмно-красная клетка с 💢, `ship` — серый корабль (на своём поле всегда, на поле соперника — только после итога).
- Строка состояния: «🟢 Ваш ход» / «🔴 Ход противника» / «🤖 Компьютер думает…» (`thinking`). Пока думает компьютер — три точки анимацией. Таймер хода — кольцо вокруг индикатора хода (`timer.left/total`), между кадрами плавное. Пропуски — «Пропуски: вы 1/3 · соперник 0/3», если не нули.
- Последние ходы (`last`) — две строки под строкой состояния, свежий ход подсвечивается на соответствующем поле кольцом на 1 с.
- Выстрел: нажатие клетки поля соперника → `press(actions.fire)`. В чужой ход клетки поля соперника неактивны (`note` «Не ваш ход!» от сервера тоже показывается).
- Мигание (`blink`): клетки `blink.cells` на указанном поле рисуются по `frame` (`hit` ↔ `sunk`). Сервер шлёт кадры сам, клиент только рисует.
- Итог (`result`): карточка поверх полей — «🏆 Победа!» / «💀 Поражение», причина (`reason`), очки, рейтинг и изменение (бой с другом), строки пути (`journey`, бой с компьютером). Кнопки — из `screen.rows`: «Новая партия…», «Дальше: …», «Меню». Поле соперника после итога показывает непотопленные корабли.
- «Сдаться» — с подтверждением (`Telegram.WebApp.showConfirm("Сдаться? Это поражение.")`), затем `press(actions.surrender)`.

## 3. Расстановка (`status: "placing"`)

- Своё поле во всю ширину. Под полем — корабли, которые ещё надо поставить (`placement.sizes` минус `fixed`), от большого к маленькому.
- **Перетаскивание** (pointer events, работает пальцем и мышью): корабль берётся из «дока» и тащится на поле; под пальцем — тень корабля, зелёная, если место допустимо (не за краем, не на `fixed` и не на `forbidden`), красная — если нет. Это только подсказка клиента. Окончательно решает сервер.
- Отпустил на допустимом месте → `press(actions.place)` с центром и ориентацией (`{o}` = `h` или `v`), затем, после ответа без ошибки, `press(actions.fix)`. Центр — как в ядре: клетка с индексом `(size-1)//2` от начала корабля (у чётных — левая/верхняя из двух средних). Ошибка (`note`) — корабль возвращается в док с анимацией.
- Кнопка «Повернуть» (подпись клиента) поворачивает корабль в доке до перетаскивания.
- «Сначала» → `actions.reset`, «Готов» (когда все стоят) → `actions.ready`. Таймер расстановки — `placement.left`, обновляется кадрами сервера раз в 30 с, между ними клиент считает сам.
- `status: "waiting_ready"` — своё поле с кораблями и «Ждём соперника…».

## 4. Приглашение (`status: "waiting"`)
Карточка с кодом крупно, кнопка «Отправить другу» → `Telegram.WebApp.openTelegramLink("https://t.me/share/url?url=" + encodeURIComponent(invite.link))`, кнопка «Скопировать код» (буфер обмена, toast «Скопировано»), «Отменить приглашение» → `actions.cancel_invite`.

## 5. Не входит
Изменения правил, алгоритма компьютера и времени хода; звуки; чат между игроками.

## 6. Тесты и критерии приёмки
1. vitest: все образцы `fixtures/sea-*.json` рендерятся, снимки DOM; выстрел шлёт `fire` с координатами; в чужой ход поле неактивно; расстановка перетаскиванием (синтетические pointer events) шлёт ровно `place` → `fix` с центром по правилу ядра и нужной ориентацией для горизонтального и вертикального корабля размером 1, 2, 3, 4.
2. Playwright против dev-сервера M1:
   - бой с компьютером (обычный, без лимита, малый, авто) до победы — ходы по `/dev/hint`; итог, «Новая партия с компьютером»;
   - ручная расстановка перетаскиванием полного набора → «Готов» → бой начался;
   - бой с другом: два контекста браузера (два dev-пользователя), приглашение по коду, по выстрелу у каждого, сдача → у второго карточка победы;
   - один игрок в Mini App, второй — в чате: проверяет Claude тестом M1, исполнителю не нужно.
   Скриншоты всех состояний на 360×640 и 414×896, обе темы.
3. Поля 8×7 + 8×7 помещаются на 360×640 без прокрутки во время боя.
4. Сдача: ветка `miniapp/m4-seafight`, отчёт с отступлениями от ТЗ, скриншоты, вывод тестов.
