# Сценарии

Сценарий — это цепочка действий игрока и ожидаемая реакция бота, записанная обычным текстом. Его пишут, пока фичу проектируют, а pytest прогоняет каждый сценарий отдельным тестом (`tests/test_scenarios.py`).

Каждый сценарий начинается со свежего бота: пустая БД, виртуальное время. После каждого шага, кроме заданных проверок, сами собой проверяются общие правила экрана: лимиты Max, нет кнопок-тупиков, кнопки совпадают с состоянием партии.

## Как работать с фичей
1. На этапе проектирования опишите путь игрока в новом файле `имя.scenario`, а над сценарием поставьте `@черновик`.
2. Пока фича не готова, сценарий падает, а тесты при этом зелёные: черновик помечается `xfail`.
3. Когда сценарий начнёт проходить, pytest упадёт с подсказкой «уже проходит — снимите метку @черновик». С этого момента сценарий — обычный регрессионный тест.

Посмотреть, что бот отвечает на каждом шаге (с игровым полем), можно так:
```bash
.venv/bin/python -m tests.scenario tests/scenarios/sea.scenario
```

## Формат
```
# комментарий
@черновик
Сценарий: Победа в малом бою попадает в рекорды
  Админ: Тестер                 # кому доступен /dbg (необязательно)
  Платформа: tg                 # max (по умолчанию) или tg — настройки Manager для Telegram
  пишу /start
  жму Морской бой
  жму Малый
  хожу верно до "Партия окончена"
  вижу "Все корабли потоплены"
  кнопки: Ещё раз | Меню
```
- Отступы и кавычки (`"…"` или `«…»`) необязательны.
- Подписи кнопок и тексты сверяются по вхождению: `жму Мемо` найдёт «🃏 Мемо». Если подходят две кнопки, шаг упадёт. Тогда возьмите кусок подписи, который есть только у нужной кнопки (`жму (малый)`).
- Текст экрана сравнивается без HTML-разметки, как его видит человек.
- Игрок по умолчанию — «Тестер». Других игроков задаёт префикс `[Имя]`: `[Боб] жму Мемо`. Каждое имя — отдельный пользователь со своим чатом.

## Шаги

| Шаг | Что делает |
|---|---|
| `пишу <текст>` | текстовое сообщение боту (`/start`, `/dbg level memo 5`, любое) |
| `жму <подпись>` | нажать кнопку по подписи |
| `жму клетку <ряд> <колонка>` | нажать клетку поля, счёт с 0 |
| `хожу верно` / `хожу верно 3 раза` | верный ход: попадание, нужная клетка, пара; если идёт отсчёт, показ, разбор или итог — дождаться его конца |
| `хожу верно до <текст>` | верные ходы, пока на экране не появится текст |
| `ошибаюсь` | ошибочный ход: промах, неверная клетка, несовпавшая пара |
| `доигрываю партию` | довести любую партию до записанного итога: матрицу — раунд и «Закончить», остальные — верными ходами |
| `выигрываю раунд` | пройти текущий раунд матрицы, поездки на числах или дороги (партия остаётся на итоге раунда) |
| `жду <N> с` | промотать время: таймеры сработают, сообщения обновятся |
| `вижу <текст>` / `не вижу <текст>` | текст есть или нет на экране |
| `уведомление <текст>` / `без уведомления` | всплывающее уведомление последнего нажатия |
| `есть кнопка <подпись>` / `нет кнопки <подпись>` | кнопка есть или нет (клетки поля не в счёт) |
| `кнопки: A \| B \| C` | ровно эти кнопки и в этом порядке (клетки поля не в счёт) |
| `открыто клеток: N` | сколько клеток поля открыто (не ⬜, не 🟨 и не пустая): карты мемо, найденные клетки, числа, дорога |
| `перехожу по ссылке` | открыть последнюю ссылку-приглашение (в бой с другом или в друзья), которую присылал бот (как `bot_started` с payload) |
| `пишу код приглашения` | прислать боту код последнего приглашения сообщением |
| `стреляю мимо` / `стреляю по кораблю` | бой с другом: выстрел в пустую клетку / в корабль (по возможности не топя его), чей бы ни был ход |
| `доводим партию до последнего выстрела` | оба по очереди топят корабли, пока каждому не останется одна клетка; ход — за этим игроком |
| `расставляю корабли` | ручная расстановка: оставшиеся корабли — нажатиями, горизонтально, в первые подходящие места |
| `перезапускаю бота` | новый Manager на той же БД: таймеры гибнут, партии с другом восстанавливаются |
| `иду кратчайшим путём` | «Проложи дорогу»: положить кратчайшую дорогу от человека к дому |
| `иду в обход` | положить дорогу длиннее кратчайшей |
| `кладу дорогу с середины` | кратчайшая дорога, начиная с её середины |
| `жму клетку дороги ещё раз` | повторно нажать последнюю клетку дороги |
| `жму на человека` / `жму на дом` | нажать клетку человека или дома |
| `на поле видны человек и дом` | на клетках человека и дома — их фигурки |
| `наступаю на препятствие` | нажать препятствие ⛔ |
| `жму чёрную клетку` | нажать чёрную клетку ⬛ вне игрового поля |
| `на поле есть <символ>` / `на поле нет <символ>` | символ есть или нет среди клеток поля |
| `числа поездки с разрывом` | в текущем раунде «Поездки на числах» есть разрыв в последовательности |
| `наступает воскресенье ЧЧ:ММ` | промотать время до ближайшего воскресенья ЧЧ:ММ по Москве (итоги недели) |
| `наступает ЧЧ:ММ` | промотать время до ближайших ЧЧ:ММ по Москве (бот стартует в 16:46) |
| `приходит сообщение <текст>` / `сообщений не приходило` | что бот прислал игроку сам (друзья, уведомления, напоминания, открытки, новые зоны пути) с прошлой такой проверки |
| `в итоге не вижу <текст>` | текста нет в сообщении последней партии |
| `в итоге вижу <текст>` | текст в сообщении последней партии: после итога бот мог прислать открытку или новую зону, и последним стало оно |
| `есть картинка` / `нет картинки` | у последнего сообщения есть картинка (путь, открытка) или нет |
| `картинка пути: зона N, шаг S` | на картинке зона N (счёт с 1), герой на шаге S; с `, герой cat` — этот герой (иначе — выбранный игроком), с `(пройдена)` — пройденная зона, с `(облака расходятся)` — только что открытая |
| `картинка — открытка N дней` | открытка за серию из N дней |

Если нужного шага нет, его можно добавить в `tests/scenario.py`: одна строка в `STEP_PATTERNS` и функция `do_…`.
