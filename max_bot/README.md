# Бот игр для Max

Бот `@id745206826404_3_bot` («Развивающие игры») для мессенджера Max. Игры: мемо, матрица памяти, башня чисел, морской бой — один и с другом (рейтинг Elo).

## Как устроено
- `games_core/` — игры без привязки к мессенджеру:
  - логика: `memo`, `matrix`, `tower`, `seafight_solo`, `seafight_mp` (бой с другом);
  - уровни: `progression`;
  - баланс очков: `scoring`;
  - экраны: `sessions`;
  - меню, рекорды и таймеры: `manager`; бой с другом — экраны, ходы и таймеры: `multiplayer`;
  - SQLite: `storage`.
  Транспорту нужно превратить `Screen` в свои кнопки и уметь три вещи: ответить на нажатие, править сообщение (`push`) и прислать новое (`send`). Этот же пакет целиком работает и в Telegram (`sea_fight_aiogram/games_tg.py`, `platform="tg"`): меню, игры и бой с другом там те же.
- `max_bot/` — транспорт Max на `maxapi`, webhook через Caddy china-drom.ru (или long polling, если `WEBHOOK_URL` пуст):
  - нажатие обрабатывается одним запросом `POST /answers`: ответ на callback и новая клавиатура вместе;
  - скрыть фигуры после показа и закончить минуту — через `PUT /messages` по таймеру.
- Состояние:
  - одиночные партии хранятся в памяти; после перезапуска незаконченная партия теряется;
  - бой с другом сохраняется в `mp_games` после каждого хода и после перезапуска продолжается с тем же ходом и таймерами (`Manager.restore()`);
  - уровни, рекорды и рейтинг лежат в `max_bot/data/games.db`.
- Сертификат API Max выпущен российским УЦ Минцифры. Системный curl на сервере ему не доверяет, а `maxapi` носит этот сертификат с собой (`maxapi/client/russiantrustedca.pem`).

## Правила и баланс
- Уровни матрицы и башни:
  - 3 выигрыша подряд — уровень +1;
  - 2 ошибки — уровень −1;
  - новая партия начинается с уровня, на котором закончилась прошлая;
  - если не играли больше 2 суток — на 3 уровня ниже.
- Очки:
  - верное нажатие (пара в мемо) даёт `10 × уровень × множитель серии`;
  - множитель серии: ×1, с 5 подряд — ×1.5, с 10 — ×2, с 20 — ×3, с 40 — ×4;
  - пройденный раунд даёт ещё `5 × уровень × элементов`.
- Матрица и башня:
  - перед каждым показом идёт отсчёт «3, 2, 1» (2 с), затем фигуры показываются 1 с;
  - матрица: партия — 60 с ввода (отсчёт, показ и разбор таймер не тратят), таймер с полоской обновляется сам раз в 5 с и при каждом нажатии;
  - башня: без таймера, партия — 6 раундов (`TOWER_ROUNDS`); в подсказке — дождаться, пока кнопка откроется (Max доставляет нажатие ~1 с); над полем растёт башня — этаж за каждые 50 очков (`FLOOR_POINTS`);
  - после ошибки 2 с разбор (`REVIEW_SECONDS`): найденные клетки, ошибочная ❌ и правильный ответ (в матрице — 🟩, в башне — все числа, на ошибочной «❌<число>»), потом отсчёт следующего раунда.
- Башня: клетки без чисел всегда жёлтые 🟨 и неактивны, нажатие по ним не ошибка; клетки с числами белые ⬜.
- Мемо:
  - партия — одно поле, её можно закончить досрочно;
  - поле собрано не больше чем за 2 хода на пару (`MOVES_PER_PAIR` в `games_core/memo.py`) — сразу следующий уровень;
  - собрано, но ходов больше — уровень остаётся; досрочный конец — ошибка (2 ошибки — уровень −1);
  - промах штрафуется на `5 × уровень`, только если одну из двух карт уже открывали раньше;
  - несовпавшая пара видна 3 с и закрывается сама (`MEMO_CLOSE_SECONDS`) — или раньше, следующим нажатием.
- Морской бой с другом (правила перенесены из прежней Telegram-версии):
  - «Морской бой» → «Играть с другом»: время на ход (без лимита, 10 с, 30 с, 1 мин, 5 мин, 1 ч), набор кораблей, расстановка (автоматическая или ручная);
  - приглашение — ссылка `https://max.ru/<бот>?start=mp_<код>` (приходит в `bot_started.payload`) или сам код, присланный боту сообщением;
  - у каждого игрока одно сообщение: своё поле — эмодзи в тексте, поле соперника — кнопками для выстрела, внизу «Сдаться» и «Меню»; над полями — соперник, два последних хода и чей ход с таймером;
  - первым ходит пригласивший, ход переходит после каждого выстрела; попадание +10, потопление +20;
  - победный выстрел сразу закрывает партию: ход не переходит, нажатия соперника во время мигания последнего корабля получают «Эта игра уже завершена» (в TG до 1.3.1 проигравший успевал выстрелить);
  - время хода вышло — ход сопернику; 3 пропуска — техническое поражение; «Сдаться» в бою — поражение с пересчётом рейтинга, до боя — отмена партии без рейтинга;
  - ручная расстановка: клетка — центр корабля, ещё раз — поворот, «Зафиксировать», «Готов»; 3 минуты, иначе партия отменяется;
  - рейтинг Elo (старт 1000, K=32) отдельно для полного и малого набора — в «Рекордах»: «С другом (полный/малый)»;
  - ушли из сообщения партии в меню — бот перестаёт его править; «Морской бой» → «Вернуться к партии» показывает партию снова.
- Лимиты Max, проверенные на API: не больше 7 кнопок в ряду (`errors.maxRowSize`), не больше 30 рядов (`errors.maxRows`). Поля шире 7 клеток не бывает, морской бой — 8×7.
- Константы баланса лежат в `games_core/scoring.py`, таблицы уровней — в модулях игр, тайминги — в `games_core/manager.py` (и переменных `.env`).

## Диагностика нажатий
На каждое нажатие бот пишет в лог строку `tap user=… payload=… age=…ms wait=…ms api=…ms`:
- `age` — сколько прошло от нажатия (метка сервера Max) до прихода к боту;
- `wait` — ожидание в очереди нажатий игрока;
- `api` — ответ Max на правку сообщения.
Если нажатие пропало, а строки `tap` для него нет, — до бота оно не дошло.

## Локальный запуск
```bash
python3 -m venv .venv && .venv/bin/pip install -r max_bot/requirements.txt pytest pytest-asyncio
cp max_bot/.env.example max_bot/.env   # вписать MAX_BOT_TOKEN
.venv/bin/python -m pytest
.venv/bin/python -m max_bot.main
```
Локально бот работает через long polling (`WEBHOOK_URL` пуст). Пока на проде включён webhook, polling ничего не получает. Две копии бота на одном токене тоже нельзя запускать вместе: прежде чем запускать бот локально, остановите прод (`docker compose -f max_bot/deploy/compose.yaml stop` на сервере).

## Тесты
- `tests/harness.py` — мессенджер без мессенджера. `Chat.click("Морской бой")` жмёт кнопку по подписи, `tap(r, c)` — клетку поля. Время виртуальное: `world.time.advance(60)` проматывает минуту партии мгновенно, вместе со всеми правками по таймеру.
- `tests/scenarios/*.scenario` — сценарии обычным текстом («пишу /start», «жму Морской бой», «вижу …»): их пишут при проектировании фичи, pytest прогоняет каждый. Формат описан в `tests/scenarios/README.md`.
- `tests/test_flows.py` — те же сценарии кодом, для случаев, которые текстом не описать: меню → игра → победа → рекорды, конец минуты, смена уровня, два игрока.
- `tests/test_random_walk.py` — случайный обход: 6 прогонов по 2500 действий (нажатия, сообщения, промотка времени, `/dbg`). После каждого действия проверяется:
  - экран проходит лимиты Max;
  - нет кнопок-тупиков и неизвестных payload;
  - кнопки на экране совпадают с состоянием партии;
  - результат записан ровно тогда, когда должен;
  - таймеры не падают.
  Упавший прогон выдаёт seed и последние действия.

## Отладка в мессенджере (`/dbg`)
Команды доступны только user_id из `DEBUG_USER_IDS` в `max_bot/.env`. Остальным `/dbg` показывает их id — его и нужно вписать.
- `/dbg` — прогресс по играм и кнопки быстрых действий.
- `/dbg level <игра> <уровень> [серия]` — уровень и серия побед (memo, matrix, tower). С серией 2 следующий выигранный раунд поднимет уровень.
- `/dbg idle <игра> <дней>` — будто последняя игра была N дней назад (проверка штрафа за перерыв).
- `/dbg round <сек>` — длина партии матрицы и башни только для вас; `0` — как у всех.
- `/dbg sea_end [full|reduced]` — морской бой за выстрел до победы.
- `/dbg memo_end` — мемо, осталась одна пара.
- `/dbg reset` — стереть свои уровни и рекорды.

Партии из `/dbg` настоящие: их результат попадает в рекорды. После проверки на проде стоит сделать `/dbg reset`.

## Прод (91.227.18.215, china-drom.ru, пользователь drom_root_user, без sudo)
- Бот работает в Docker-контейнере `games-bot` (`max_bot/deploy/compose.yaml`, отдельный compose-проект `games-bot`).
  - Контейнер подключён к сети `china-cars_default`: Caddy china-cars проксирует `https://china-drom.ru/hooks/games/<секрет>` на `games-bot:8445`. Порт хоста не публикуется, ufw пропускает только 22/80/443.
  - Перезапуск после падения и перезагрузки сервера делает Docker (`restart: unless-stopped`), лимит памяти 160 МБ.
- Выкладка: `./max_bot/deploy/deploy.sh`. С ключом `--env` скрипт копирует и локальный `max_bot/.env`.
- Код лежит в `~/games_bot`, база — `~/games_bot/max_bot/data/games.db`, логи — `~/games_bot/logs/max_bot.log` (ротация 5 МБ × 3).
- Каждое действие на сервере записывается в `~/claude-ops.log`.

### Webhook или long polling
- Режим задаёт `max_bot/.env` на сервере:
  - `WEBHOOK_URL=https://china-drom.ru/hooks/games/<секрет>` и `WEBHOOK_SECRET=<секрет>` — webhook. При старте бот сам подписывает этот URL.
  - Без `WEBHOOK_URL` — long polling.
- Тот же секрет записан в `GAMES_WEBHOOK_SECRET` в `~/china_cars/infra/prod/.env`. Маршрут в Caddyfile china-cars описан в их `infra/prod/README.md`.
- Подписки: `docker compose -f max_bot/deploy/compose.yaml exec games-bot python -m max_bot.webhook list|subscribe|unsubscribe`.
- Вернуться к polling: `unsubscribe`, затем убрать `WEBHOOK_URL` из `.env` и выполнить `docker compose … up -d`. Пока подписка есть, polling ничего не получает.
- Max шлёт только на HTTPS:443. Если 8 ч подряд нет ответа 200, он снимает подписку сам. Тогда после долгого простоя сделайте `subscribe` (или просто перезапустите бота).
- Смена секрета: `unsubscribe` → новый секрет в обоих `.env` → `docker compose up -d caddy` у china-cars → перезапуск бота.
