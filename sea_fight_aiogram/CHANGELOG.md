# Changelog

Все изменения проекта Sea Fight Bot будут задокументированы в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
и этот проект придерживается [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.3.0] - 2026-10-18

### Добавлено
- Мемо, Матрица памяти и Башня чисел — те же игры, что у бота в Max, на общем ядре
  `games_core`. Транспорт — `games_tg.py`, прогресс и рекорды — SQLite `data/games.db`
- Главное меню как в Max: Мемо · Матрица памяти · Башня чисел · Морской бой · Рекорды.
  Морской бой (одиночная игра, игра с другом, Elo) — отдельное меню, без изменений
- Отладочные команды `/dbg` для игр ядра (`DEBUG_USER_IDS`)
- Лог в файл с ротацией (`LOG_FILE`), строка `tap` на каждое нажатие в играх ядра
- User-юнит systemd `deploy/games-tg-bot.service` и отдельный venv бота

### Изменено
- Главное меню — текстом, без картинки `seafight.jpg`
- Любое текстовое сообщение открывает главное меню

## [1.2.0] - 2026-09-14

### Исправлено — критическое
- Партия в мультиплеере завершалась вхолостую: игроки не получали результат,
  записи в таблицах не появлялись, память об игре не очищалась. Причина в SQL —
  в `update_multiplayer_stats` внутри `ON CONFLICT DO UPDATE` стоял
  неквалифицированный `user_id`, неоднозначный для PostgreSQL (в области
  видимости и колонка таблицы, и `excluded`). `AmbiguousColumnError` вылетал
  до рассылки сообщений и обрывал `finish_mp_game` на середине
- Шаги завершения партии изолированы `try/except`: сбой статистики или рейтинга
  больше не может оставить игроков без уведомления об итоге
- `turn_start_time` не обновлялся при ходе — записывался только `last_move_time`,
  из-за чего отсчёт времени шёл от начала партии, а не от начала текущего хода

### Добавлено
- Рейтинг мультиплеера по системе Elo (старт 1000, K=32), раздельно для полного
  и сокращённого набора кораблей — таблица `player_ratings` с миграцией
  `add_player_ratings.sql`; создаётся и через `init_tables`, ручной прогон
  миграции для чистой установки не нужен
- Итог партии приходит игрокам вместе с новым рейтингом и его изменением
- Таймер хода виден прямо в сообщениях с досками; период перерисовки зависит
  от лимита времени (от 5 с при коротких лимитах до 60 с при часовом)
- Анимация потопления корабля в мультиплеере — мигание у обоих игроков сразу.
  Выполняется фоновой задачей и не блокирует ходы; если за это время кто-то
  успел сходить, оставшиеся кадры пропускаются
- Результат хода противника виден в шапке доски (попал / потопил / промахнулся);
  данные берутся из истории атак, поэтому строка переживает рестарт бота
- Имена обеих сторон в сообщениях: кто приглашал и кто подключился,
  плюс постоянная строка «Вы против <соперник>» над досками
- Сквозной номер хода (`seq`) в истории атак

### Изменено
- Таблица рекордов одиночной игры показывает по одной строке на игрока — его
  лучший результат и дату; при равных очках выше более свежий результат
- Позиция в таблице считается по лучшему результату игрока, а не по счёту
  только что сыгранной партии
- Таблица мультиплеера показывает топ по рейтингу вместо разовых результатов
- Имя игрока определяется как username → имя из Telegram → числовой id
- Имена выводятся без «@», иначе Telegram делает из ника ссылку на профиль
- Два последних хода в шапке доски идут в хронологическом порядке, а текущий
  ход — последней строкой вместе с обратным отсчётом
- Всплывающие сообщения («Потопил», «Ранен», «Мимо» и служебные) переведены
  на язык интерфейса; английские литералы заменены ключами i18n
- После рестарта бота таймер хода досчитывает остаток времени, а не начинает
  полный лимит заново
- Шапка над досками собирается одной функцией `build_board_header`
- `update_mp_boards` делает два запроса к БД на перерисовку вместо четырёх

### Исправлено — отображение
- Таблица рекордов печаталась вместе с тегами `<b>`: `edit_message_safe`
  не передавал `parse_mode`. Глобальный HTML-режим сознательно не включён —
  имена игроков приходят из Telegram и не валидируются, поэтому каждое имя
  экранируется через `html.escape`

### Удалено
- Механика пользовательского ника для таблицы рекордов (`leaderboard_name`),
  включая одиночную игру: запрос имени после победы, ввод ника текстом, кнопки
  выбора имени и отказа от таблицы. Колонка в БД оставлена, код её не использует

## [1.1.0] - 2026-06-12

### Исправлено — критическое
- `NameError` при переходе по недействительной ссылке-приглашению (`/start mp_XXX`)
- Второй игрок не мог нажать «Я готов» при ручной расстановке: `game_id` не сохранялся
  в его FSM-состоянии (добавлен и fallback-поиск активной игры через БД)
- `time.sleep` в анимации потопления блокировал event loop всего бота
  (заменён на `await asyncio.sleep`)
- `init_tables` падал на чистой базе: миграция `ship_set` выполнялась до создания
  таблицы `multiplayer_games`; в схему добавлена колонка `join_code` —
  чистая установка больше не требует ручного запуска миграций
- Лимит времени на ход не применялся: реализован таймер хода — по таймауту ход
  переходит противнику, после 3 пропусков засчитывается техническое поражение

### Исправлено — логика игры
- Повторный выстрел в клетку с промахом больше не снимает очки повторно
  (промах помечается и на скрытой доске)
- Гонки при одновременном нажатии «Я готов»: активация игры стала атомарной
  (доски рассылаются один раз), доска сохраняется точечно — флаги готовности
  оппонента не затираются устаревшими данными
- Таймаут расстановки помечает игру `abandoned` в БД и уведомляет оппонента —
  зависшая игра больше не блокирует создание новых
- Состояние «ранен» (💢) корректно отображается на своей доске; при потоплении
  все клетки корабля на доске атаки помечаются 💥
- Результаты мультиплеера записываются в лидерборд (`mp_full` / `mp_reduced`),
  добавлена таблица рекордов для сокращённого набора
- Приоритет операторов `OR`/`AND` в SQL-запросе `check_frequent_games`

### Добавлено
- Восстановление активных игр и таймеров ходов после рестарта бота;
  пересылка игровых досок, потерянных при рестарте
- Сообщение с кнопками главного меню, если одиночная игра потеряна после рестарта
- Проверка `BOT_TOKEN` при старте с понятным сообщением об ошибке
- Валидация имени из Telegram перед записью в лидерборд

### Изменено
- Таймер расстановки показывает точное оставшееся время; таймаут срабатывает вовремя
- `utils/ship_placement.py` использует размеры поля и символы из `config.py`
  вместо зашитых констант
- Три копии построения интерфейса расстановки объединены в `build_placement_view`
- Выбор времени на ход обрабатывается только в соответствующем состоянии FSM
  (устаревшие кнопки не срабатывают)
- Кнопка возврата из лидерборда в меню подписана «🏠 Главное меню»

### Удалено
- `multiplayer_bot.py` — неиспользуемый дубликат бота с тем же токеном

## [1.0.0] - 2026-05-05

### Добавлено
- Полный перенос бота с python-telegram-bot на aiogram 3.x
- Замена MySQL на PostgreSQL (asyncpg)
- Модульная архитектура проекта
- Асинхронная работа с базой данных
- Поддержка мультиязычности (en/ru)
- Лидерборд с сохранением результатов
- Игровое поле 8x8 с автоматической генерацией кораблей
- Анимация потопления кораблей
- README с инструкциями
- INSTALL.md с подробным руководством по установке
- .env для безопасного хранения конфигурации
- Gitignore для Python проектов
- Setup.py для установки как пакет

### Изменено
- python-telegram-bot → aiogram 3.x
- mysql-connector → asyncpg
- Синхронный → асинхронный код
- Монолитный файл → модульная структура

### Технические улучшения
- Индексы в базе данных для быстрого поиска
- Автоматическое обновление `updated_at` через триггер
- Чистое разделение ответственности (MVC паттерн)
- Type hints для улучшения читаемости кода
- Docstrings для документации
